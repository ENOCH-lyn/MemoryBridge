## ADR-001：自进化边界——外部经验记忆，不做权重更新

**状态：已确认｜日期：2026-10-21｜复审：答辩前**

### 背景

用户的目标是“AI 自进化，通过跨项目共享实现经验积累”。但“自进化”在工程上有三种可能：参数更新（微调/LoRA）、隐状态/缓存、外部记忆。前两者需要训练数据、算力与评测，且存在灾难性遗忘、隐私和不可解释问题；课程周期内不可行，也不适合“个人记忆”场景。

### 决策

本项目只做 **token-level 的外部记忆**，不训练、不微调模型。把“自进化”定义为：

> 在不更新模型权重的前提下，把任务轨迹转化为可检索、可验证、可复用的经验记忆；同类任务再次出现时，agent 调用这些经验，从而在成功率、轮次或 token 成本上获得可测量改进。

配套假设：

- **H1**：结构化经验记忆优于原始对话 RAG；
- **H2**：验证后晋升的经验优于未验证候选；
- **H3**：治理（冲突/时效/来源）降低错误记忆导致的错误率。

### 备选

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 微调/LoRA | 可能内化风格与流程 | 数据/算力/评测重；隐私与遗忘风险 | 不做 |
| 参数化记忆（如记忆层） | 推理时直接生效 | 研究性强、不可审计、课程周期不可行 | 不做 |
| 提示词里塞全部历史 | 实现最简单 | 窗口有限、成本高、无治理 | 仅作基线 B1 |
| 外部结构化记忆 | 可审计、可迁移、可删除 | 抽取与治理工程量大 | **采用** |

### 后果

- 正面：主张可证伪；记忆可读、可改、可删；跨设备迁移自然。
- 代价：效果上限受抽取/检索质量限制；“进化”需要评测证明，不能靠叙事。
- 若 H1–H3 不成立：报告负结果与边界条件，仍是合格研究产出。

### 验证与回滚

以 CrossProjectBench 的迁移增益、消融和误差分析验证；不以“演示感觉更好”作为证据。若外部记忆无增益，回退到“文档库 + 检索”轻量定位，不改变“不微调”的边界。

## ADR-002：产品范围——单用户、自部署、课程 MVP

**状态：已确认（课程范围）｜日期：2026-10-21｜复审：W1 教师确认**

### 背景

完整愿景包含个人、项目、团队三类空间，跨设备、跨 agent、文档库与经验复用。若全部纳入 12 周课程，必然延期；需要一条能演示、能评测、能写论文的最小闭环。

### 决策

课程 MVP 锁定：

- **单用户**；2 台设备；3 个 agent（Claude Code / Cursor / DSH）；3 个项目。
- 自部署 Hub + MCP 接入 + Web 控制台。
- 核心闭环：采集 → 提炼 → 治理 → 检索注入 → 经验晋升。
- 文档库与 Git 版本作为 P1；团队/多租户 P2。

**非目标**：多租户 SaaS、计费、企业 SSO、实时多人协同、移动端 App、端到端加密、通用图数据库运维、模型微调。

### 备选

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 全功能 Memory OS | 愿景完整 | 12 周不可交付 | 不做 |
| 只做 MCP 记忆 CRUD | 最快 | 无治理/同步/经验，创新不足 | 仅作降级方案 |
| 单用户 MVP + 跨项目评测 | 可交付、可证伪 | 团队能力后置 | **采用** |

### 后果

- 正面：范围可控；演示故事完整；论文问题聚焦。
- 代价：团队场景不覆盖；部分设计需为 P2 预留接口（space、ACL、审计）。
- 评审风险：被问“为什么不做多人”——用范围与课程周期回答，并给出 P2 触发条件。

### 验证与回滚

W1 与教师确认课程要求；若要求团队版，砍掉经验晋升或图扩展，保同步 + 治理 + 文档。若团队人数不足 3 人，进一步砍到“单机 + 双客户端 + 检索”，不做跨设备同步。

## ADR-003：接入协议——MCP 优先，CLI/Hook 补充

**状态：已采纳（工程）｜日期：2026-10-21｜复审：W4**

### 背景

目标 agent 包括 Claude Code、Cursor、Codex、DSH 等，各自插件机制不同。为每家写一套适配器维护成本高，且新 agent 不断出现。MCP 已成为跨 agent 的事实标准（当前规范 2025-11-25）。

### 决策

- **MCP 优先**：提供 stdio 本地代理与 HTTP 远程两种形态；暴露 Tools（`memory_search` / `memory_add` / `memory_update` / `memory_forget` / `memory_feedback` / `context_pack` / `skill_list`）、Resources（`memory://`、`doc://`）与 Prompt（`recall_for_task`）。
- **CLI/Hook 补充**：`mb` 命令负责登录、同步、手动记忆、导入；Hook 负责会话边界与工具摘要采集。
- **版本协商**：按 MCP 版本协商；不支持 Resources 的客户端降级为 Tools。
- **fail-open**：检索失败返回空结果 + 警告，不阻塞主任务；写入失败进本地 outbox。
- **调研补充（2026-10-21）**：MCP `InitializeResult.instructions` 是可选字段，规范只说客户端 **MAY** 注入；不能假设所有客户端都会把它放进模型上下文。启动协议需要 `instructions` + 工具描述 + Bootstrap Gate + CLI 兜底，详见[开源复用调研](../调研/MemoryBridge-开源复用调研.md)。

### 备选

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 每家写插件 | 体验可定制 | 维护爆炸、覆盖慢 | 不做 |
| 仅 REST API | 简单 | agent 需自行集成，采用率低 | 仅作底层 |
| MCP + CLI/Hook | 跨 agent、可渐进 | 受 MCP 规范演进影响 | **采用** |

### 后果

- 正面：一次接入，多 agent 复用；协议层可独立升级。
- 代价：MCP 规范可能变化；本地代理多一跳；不同客户端对 Resources/Prompt 支持不一致。
- 安全：MCP 工具是 agent 可调用的写入口，必须做 token 作用域、速率限制与审计。

### 验证与回滚

W4 用 3 个 agent 完成“检索 → 注入 → 写回”闭环；记录各客户端版本与能力差异。若某客户端不兼容，降级为 CLI + REST，不阻塞其他 agent。

## ADR-004：记忆模型——Episode + 结构化 Memory Item + Provenance

**状态：已采纳（工程）｜日期：2026-10-21｜复审：W5**

### 背景

只存聊天切片会导致“检索得到但不可治理”：无法判断新旧、无法去重、无法追溯出处。只存知识图谱则抽取成本高、冷启动难。个人记忆需要“少而准”，且每条都能回溯。

### 决策

两层模型：

1. **Episode**：原始证据，只追加。字段含 `space_id`、`device_id`、`agent_id`、`occurred_at`、`content`、`content_hash`、`sensitivity`、`meta`。
2. **Memory Item**：从 Episode 提炼的结构化记忆。类型为 `fact` / `preference` / `decision` / `lesson` / `procedure` / `reference`；字段含 `content`、`structured(jsonb)`、`status`、`confidence`、`importance`、`valid_from/to`、`scope`、`entities`、`evidence[]`、`version`、`hash`。

关系用 `memory_edges` 表达：`relates_to` / `derived_from` / `supersedes` / `contradicts` / `applies_to`。文档块以 `reference` 类型进入同一索引，保留文档 ID、版本与章节锚点。

**硬规则**：无 `evidence` 不写 Memory Item；`evidence` 必须指向 Episode 或文档块；删除采用软删除 + 墓碑。

### 备选

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 原始对话切片 + 向量 | 实现快 | 不可治理、重复、无时效 | 仅作基线 B2 |
| 纯知识图谱 | 关系强 | 抽取重、冷启动难、运维重 | P2 可选 |
| 结构化 Item + 轻量边 | 可治理、可解释 | Schema 与抽取成本 | **采用** |

### 后果

- 正面：可审计、可去重、可时效、可跨项目；文档与记忆统一检索。
- 代价：抽取质量成为瓶颈；Schema 需演进；Episode 存储增长需保留策略。
- 权衡：不追求“全自动知识图谱”，先保证“少而准”。

### 验证与回滚

200 条标注集上抽取精确率 ≥0.80；100% 记忆有 evidence；冲突注入全部可追溯。若精确率不达标，先收紧类型与 few-shot，不降级为纯切片。

## ADR-005：写入与治理——AI 直接写 + topic/scope/audit

**状态：已替代旧版（2026-10-21）｜复审：W5**

> 旧版“自动采集 + 候选/审核”已被本决策替代。用户明确要求：AI 有意识地调用 MCP 写入，UI 只读，不存在候选队列/人工批准。

### 背景

全自动文本抽取会把项目结论写成无场景的全局规则；人工审核又违背“AI 自己维护”的产品定位。正确边界是：**AI 在用户提出持久要求时主动写，服务端用 topic/scope/rationale/conditions + audit 治理**。

### 决策

- **入口**：`memory_write`（记忆）、`doc_add`（文档）、`skill_install`（技能文件夹）、`identity_update`（人格）。
- **状态**：写入即 `active`，没有 `candidate` / `approve` / `reject` UI。
- **topic**：必须提供稳定 lowercase key（如 `decision.storage`）；同 project + topic 的后续写入更新同一条，version + 1。
- **scope**：默认当前 project；`global` 只能用于用户级偏好，不能把项目决策写成全局规则。
- **质量门槛**：`decision` / `lesson` 必须有 `rationale`；建议写 `conditions`。服务端拒绝缺失 rationale 的写入。
- **审计**：所有写入落 `audit_log`；UI「活动」只读展示。
- **UI**：只读；不提供采集、候选、编辑、上传。

### 备选

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 自动抽取 + 候选/审核 | 错误不直接污染 | 违背 AI 自主维护；审核负担 | 不做 |
| 纯自由文本写入 | 简单 | 近似重复、无场景、不可治理 | 不做 |
| AI 主动写 + topic/scope/audit | 低摩擦 + 可治理 | 依赖 agent 判断 | **采用** |

### 后果

- 正面：零审核队列；记忆有 topic/scope/理由/条件；可回看审计。
- 代价：agent 必须在正确时机写；没有人工兜底。用 bootstrap instructions、tool description 和 rationale 强制约束。
- 风险：错误写入直接 active；通过 audit、version、topic upsert 和后续修正降低影响。

### 验证与回滚

- 隔离 Codex + 真实 OpenAI 兼容端点实测：`agent_bootstrap → memory_write → memory_search`，写回 `decision.storage` 并读到 `conditions`；`identity_update` 写入 persona 后 version 3。
- 若出现严重污染，回滚到旧版候选流程需要恢复已删除的 UI/表字段；当前选择是保持只读 UI + 可审计修正。

## ADR-006：同步模型——服务端权威 op log + 客户端游标

**状态：已采纳（工程）｜日期：2026-10-21｜复审：W7**

### 背景

多设备需要离线写、增量同步、冲突可解释。全文 CRDT 能自动合并，但实现与调试成本高；记忆条目是“小对象 + 字段”，冲突频率低，不需要全文协同编辑的能力。

### 决策

- **服务端权威**：客户端可离线写，恢复后推送；服务端是排序与冲突裁决的权威。
- **不可变 op log**：每个写操作生成 `op_id`（ULID）、`device_id`、`agent_id`、`hlc`、`op_type`、`entity_id`、`base_version`、`payload`、`created_at`。
- **幂等**：`op_id` 唯一索引；重复推送返回已应用结果。
- **变更流**：服务端为每个 op 分配单调 `seq`；客户端 `GET /v1/sync/changes?since=seq` 拉取，应用后更新游标；墓碑同样传播。
- **离线**：客户端 SQLite outbox + 指数退避 + 手动重试；断网可写，恢复后按序推送。
- **顺序**：同一实体按 HLC 排序；跨实体不要求全局顺序。

### 备选

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 全文 CRDT（Automerge/Yjs） | 自动合并、离线强 | 复杂、体积大、审计难 | 不做 |
| Git 同步记忆 | 版本清晰 | 语义合并弱、实时性差 | 仅用于文档 |
| 服务端 op log + 游标 | 简单、可审计、易测 | 冲突需显式处理 | **采用** |

### 后果

- 正面：协议简单；可重放、可审计；与文档 Git 分离，职责清晰。
- 代价：服务端不可用时不能跨设备同步（离线仍可本地写）；冲突需要 UI；op log 需要清理/归档策略。
- 规模：单用户 10 万条记忆、10 台设备以内足够；更大规模再评估分片。

### 验证与回滚

3 个模拟设备、随机 200 op（含并发编辑、删除、断网 30%）最终状态哈希一致、无丢失更新、重放幂等。若冲突率超预期，先加字段级锁/提示，不改用 CRDT。

## ADR-007：冲突解决——字段级合并 + 冲突副本 + 人工裁决

**状态：已采纳（工程）｜日期：2026-10-21｜复审：W7**

### 背景

“最后写入覆盖”会静默丢数据；全自动语义合并会掩盖真实矛盾。个人记忆里，部署环境、偏好、决策理由都可能被两端同时修改。

### 决策

- 每条记忆维护 `version`（整数）与 `version_vector`（device_id → counter）。
- 推送带 `base_version`：
  - `base_version == current`：直接应用，`version+1`。
  - `base_version < current` 且字段不相交：字段级合并。
  - 字段相交：保留两份，生成冲突副本，原条目保持，进入审核队列。
  - 删除 vs 更新：墓碑优先；更新进入“待恢复”队列，可人工恢复。
- 新旧事实矛盾：不自动覆盖；新事实 `active`，旧事实 `superseded` 需证据或人工确认。
- 文档冲突：Git 合并；冲突标记进审核；二进制保留两份。

### 备选

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 最后写入覆盖 | 简单 | 静默丢数据 | 不做 |
| 条目级锁 | 无并发冲突 | 离线体验差 | 不做 |
| 字段合并 + 冲突副本 | 不丢数据、可解释 | UI/状态机复杂 | **采用** |

### 后果

- 正面：不丢更新；冲突可见、可裁决；审计完整。
- 代价：冲突副本会短期增加条目；用户需要理解“冲突”概念；需要控制台支持。
- 规则：冲突未解决时，检索降低该条权重并标注“存在冲突”。

### 验证与回滚

注入 20 组并发修改/删除/矛盾，全部进入预期队列；无丢失更新；冲突解决后检索权重恢复。若冲突 UI 成为瓶颈，先做批量裁决，不改合并语义。

## ADR-008：存储——PostgreSQL + pgvector + 全文检索

**状态：建议（W2 spike 后定）｜日期：2026-10-21｜复审：W2**

### 背景

需要同时支持：事务写入、关系查询、全文检索、向量检索、JSONB 结构化字段、审计与迁移。候选是“一个 Postgres 全包”与“专用向量库 + 图库 + 关系库”的组合。

### 决策（当前基线）

- PostgreSQL 16 + `pgvector`（HNSW）+ `tsvector`/GIN；`jsonb` 存结构化字段；递归 CTE 做 1–2 跳关系。
- Redis 仅用于队列/缓存，不是事实来源。
- 单库、单机起步；预留 `EmbeddingStore` / `GraphStore` 接口，规模或查询复杂度超限再替换。

### 备选

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| SQLite + sqlite-vec | 极简、单文件、离线友好 | 并发/多设备/迁移弱 | 降级备选 |
| Postgres + pgvector + FTS | 一库多用、事务、运维简单 | 向量规模上限、图查询一般 | **基线** |
| Qdrant + Neo4j + Postgres | 向量/图能力最强 | 三套运维、一致性复杂 | P2 评估 |

### 后果

- 正面：一套备份/迁移/权限；事务保证 op log 与记忆一致；课程部署简单。
- 代价：pgvector 在 10 万级以上需调参/分片；图查询不如专用图库；embedding 维度需固定。
- 数据：向量可多模型并存（`model` + `dim`），迁移时重建。

### 验证与回滚

W2 spike：5 万条记忆、4C8G，检索 p95 ≤400ms；写入/同步不锁表；备份恢复可用。若不达标，先调 HNSW/分区；仍不达标则把向量检索迁到 Qdrant，Postgres 保留事实与 op log。SQLite 仅作为单机演示降级。

## ADR-009：检索——混合召回 + 图扩展 + 重排 + Context Pack

**状态：建议（W6 评测后定）｜日期：2026-10-21｜复审：W6**

### 背景

纯向量检索对精确术语/代码符号不稳；纯 BM25 对同义表达不友好；把全部记忆塞进上下文成本高且引入噪声。个人记忆需要“少而准、有出处、可解释”。

### 决策

两阶段：

1. **召回**：BM25 top50 + 向量 top50；RRF 融合；按 space/time/status 过滤；1-hop 图扩展（`relates_to` / `derived_from` / `supersedes`）。
2. **精排与打包**：可选 `bge-reranker-v2-m3`；综合 `rerank + utility + confidence + recency + scope_prior + type_prior`；MMR 去冗余；按 token 预算（默认 1500）裁剪；每条附 `[mem:ID]`、置信度与时效提示。

反馈：`used` / `helpful` / `harmful` / `wrong` 更新 utility；冲突/过期条目降权并标注。降级：向量服务不可用时退化为 FTS + 图扩展。

### 备选

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 纯向量 | 语义强 | 术语/符号不稳、不可解释 | 仅基线 B2 |
| 纯 BM25 | 精确、快 | 同义弱 | 降级路径 |
| 混合 + 重排 + 预算 | 稳、可解释 | 调参与成本 | **采用** |
| 全上下文 | 简单 | 贵、窗口限制 | 仅基线 B1 |

### 后果

- 正面：术语与语义兼顾；引用可点击；token 可控；可消融。
- 代价：多路召回与重排增加延迟；权重需评测调参；embedding 成本。
- 指标：P@5、R@5、NDCG@5、Context Pack 命中率、token 使用、延迟 p95。

### 验证与回滚

100 条查询（中英各半，含时间/冲突/跨项目）P@5 ≥0.70；消融去图/去重排。若重排收益不显著，默认关闭以省成本；若向量不稳，提高 BM25 权重。

## ADR-010：经验生命周期——候选 → 验证 → 晋升 → 退役

**状态：已采纳（工程）｜日期：2026-10-21｜复审：W9**

### 背景

“经验复用”是本项目的创新核心，但经验可能是错的、过期的、只适用于特定项目的。直接自动共享会造成负迁移，比没有记忆更糟。

### 决策

- **反思**：任务结束后生成 reflection（目标、步骤、卡点、可复用点、成功/失败）。
- **候选**：抽取为 Skill Schema：`trigger`、`preconditions`、`steps`、`evidence`、`counterexamples`、`scope`、`status`。
- **验证**：沙箱重放 / 人工确认 / 相似任务 A-B，至少一种通过；记录验证方式与结果。
- **晋升**：`candidate → validated → project skill → global skill`；global 需人工确认 + 证据 ≥2 + 无未解决冲突。
- **退役**：低成功率/长期未用/被新版本取代 → `deprecated`；不再默认注入。
- **负迁移防护**：scope guard、冲突警告、失败回滚；跨项目误用可一键撤销。

### 备选

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 自动全量晋升 | 零摩擦 | 负迁移/污染 | 不做 |
| 只存事实，不存技能 | 简单 | 失去“经验复用” | 不做 |
| 候选 + 验证 + 晋升 | 可控、可测 | 验证成本 | **采用** |

### 后果

- 正面：经验可解释、可回滚；可用成功率与迁移增益评估；符合“自进化”的可证伪定义。
- 代价：验证需要沙箱/人工；冷启动慢；Skill Schema 需演进。
- 指标：晋升数、验证通过率、使用次数、成功率、负迁移率、退役率。

### 验证与回滚

W9 至少 3 条 Skill 完成晋升；CrossProjectBench 上 H2（验证优于未验证）可测。若验证成本过高，先用人工确认，沙箱重放放 P1；若负迁移高，收紧 scope 与晋升门槛。

## ADR-011：文档——Markdown + Git 为真相

**状态：已采纳（工程）｜日期：2026-10-21｜复审：W8**

### 背景

用户要“维护云端文档库”，且文档要能被 agent 引用。数据库 WYSIWYG 便于协作但锁定格式；纯 RAG 文件便于检索但不可治理。Markdown + Git 人可读、可 diff、可迁移、可离线。

### 决策

- **canonical**：每个 space 一个 Git 仓库，Markdown 文件为真相；frontmatter 存元数据；`[[wiki-link]]` 建关系。
- **版本**：保存即 commit；控制台支持 diff/history/回滚；冲突用 Git 合并，冲突标记进审核。
- **索引**：文档按标题/页切块，保留 `document_id`、`git_commit`、`anchor`；作为 `reference` 记忆入索引。
- **附件**：二进制进对象存储（MinIO/S3），Git 只存引用与校验和。
- **兼容**：Obsidian 可直接打开；导出 vault 为 P2。

### 备选

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 数据库 WYSIWYG | 协作体验好 | 锁定、diff 弱、迁移难 | 不做 |
| 纯文件 + 向量 | 简单 | 无版本/无治理 | 不够 |
| Markdown + Git | 可读、可版本、可迁移 | 无实时协作、二进制弱 | **采用** |

### 后果

- 正面：文档与记忆同源；引用可到章节；用户可用熟悉工具编辑。
- 代价：Git 冲突对非技术用户不友好；大附件需对象存储；实时协作不支持。
- 规则：文档修改也走审计；敏感文档按 space ACL 隔离。

### 验证与回滚

W8 上传 10 份 PDF/DOCX/MD，解析成功率 ≥90%；回答可引用到“第 3.2 节”；Git 历史可回滚。若解析质量差，先限制格式（MD/PDF），DOCX 放 P1。

## ADR-012：身份与权限——本地账号 + 设备 token + Space ACL

**状态：已采纳（工程，MVP）｜日期：2026-10-21｜复审：W4**

### 背景

自部署单用户也需要认证：设备要撤销、agent 要限权、space 要隔离。完整 OIDC/SSO 对课程项目过重，但“无认证”不可接受。

### 决策

- **账号**：本地账号 + Argon2 密码哈希；会话 Cookie `HttpOnly` + `SameSite`。
- **设备**：每设备独立 token（哈希存储），可撤销；设备列表显示最后同步。
- **Agent**：agent token 绑定 space 与读写范围（如只读、可写、可晋升）。
- **授权**：space 级 ACL；查询强制过滤；跨 space 读取默认拒绝。
- **审计**：登录、token 撤销、权限变更、删除、晋升均记录。
- **暂缓**：OIDC/SSO、团队角色、邀请链接（P2）。

### 备选

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 无认证 | 最简单 | 任何本机进程可读 | 不做 |
| 共享 API key | 简单 | 无法撤销/审计细粒度 | 不做 |
| 本地账号 + 设备 token + ACL | 可控、可审计 | 需实现账号/令牌 | **采用** |
| OIDC/SSO | 企业友好 | 课程过重 | P2 |

### 后果

- 正面：最小可用安全边界；设备丢失可撤销；agent 可限权。
- 代价：自建账号体系；无 SSO；多用户团队需扩展。
- 风险：自部署在公网时必须 TLS + 强密码 + 限流，否则 token 易被撞库。

### 验证与回滚

越权测试：项目 B 读不到项目 A；撤销设备后 1 分钟内拒绝写入；agent 只读 token 不能写。若实现成本超预期，先做单账号 + 设备 token，space ACL 用简化规则（personal/project 两级）。

## ADR-013：安全与隐私——脱敏、信任级、E2EE 暂缓

**状态：已确认（隐私底线）+ 已采纳（工程机制）｜日期：2026-10-21｜复审：W10**

### 背景

记忆库会积累代码、密钥、决策与个人信息；一旦泄露或投毒，影响长期。自部署降低第三方风险，但不等于安全。端到端加密（E2EE）与服务端 embedding/检索存在根本冲突。

### 决策

- **采集前脱敏**：正则（API key/JWT/私钥/密码）+ 高熵字符串 + 可选 LLM 判定；`secret` 级直接阻断，不落库。
- **信任级**：`unverified` / `verified` / `trusted`；外部文档/网页默认 `unverified`；全局晋升需 `verified` + 人工。
- **提示注入防护**：记忆内容包裹为“数据”，指令性内容标记；不可信来源不参与工具授权与全局晋升。
- **传输/静态**：TLS；磁盘/对象存储加密；备份加密。
- **审计与删除**：追加写审计；软删除 + 墓碑；彻底删除传播到向量、缓存与备份标记。
- **E2EE**：**暂缓**。若要做，需客户端 embedding 或可搜索加密，检索质量/成本/复杂度显著上升；P2 专项设计。

### 备选

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 一开始 E2EE | 最强隐私 | 服务端无法 embedding/治理；课程不可行 | 暂缓 |
| 服务端可读 + TLS/静态加密 | 检索可用；磁盘/备份加密；实现简单 | 拥有服务器者仍可读明文 | **MVP 采用** |
| 字段级加密 | 部分字段不可读 | 检索/排序受限，密钥管理复杂 | P2 评估 |

### 后果

- 正面：MVP 可做检索与治理；自部署 + 脱敏 + ACL 覆盖主要风险。
- 代价：服务端（或拥有服务器的人）可见明文；E2EE 承诺不能写进 MVP。
- 底线：文档与 UI 不得宣称“端到端加密”；密钥零落库；删除必须可验证。

### 验证与回滚

50 条含密钥样本 0 落库；20 条投毒样本 ≥90% 标记；越权测试全拒绝；删除后检索/导出不可见。若安全测试失败，先阻断写入并降级为“只读记忆”，修复后再开放。

## ADR-014：部署——单机 Docker Compose

**状态：已采纳（工程）｜日期：2026-10-21｜复审：W3**

### 背景

用户要“自部署”，可能跑在 VPS、NAS 或家用服务器。课程演示与个人使用都不需要 K8s；但需要一键起、可备份、可迁移。

### 决策

- **单机 Docker Compose**：Caddy（TLS/反代）+ api + worker + web + Postgres(pgvector) + Redis + MinIO。
- **资源**：最低 2C4G/40GB；推荐 4C8G/100GB。
- **网络**：只暴露 443；内部服务不映射公网。
- **备份**：每日 `pg_dump` + 对象存储；`restic` 加密；每学期至少 1 次恢复演练。
- **升级**：镜像 tag + 迁移脚本 + 回滚说明；数据卷与配置分离。
- **可观测**：`/healthz`、`/readyz`；Prometheus 指标（P1）；结构化日志 + request_id。

### 备选

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| K8s | 弹性/多租户 | 运维重、课程不需要 | 不做 |
| 托管 PaaS | 省运维 | 数据不在自己手里、成本 | 不做 |
| 单机 Compose | 简单、可迁移、成本低 | 单点故障 | **采用** |

### 后果

- 正面：15 分钟可装；成本 <¥100/月；数据可打包带走。
- 代价：单点故障；无自动扩缩容；备份恢复需人工演练。
- 约束：不在同一台机器上同时跑生产与实验；备份与数据库分离存放。

### 验证与回滚

W3 新机器 `docker compose up -d` 15 分钟内可用；恢复演练 RTO ≤1h、RPO ≤24h。若资源不足，先减 worker 并发/关闭重排，不改成云托管。

## ADR-015：复用策略——自研薄流水线，接口可替换

**状态：待决策（W2 前）｜日期：2026-10-21｜复审：W2**

### 背景

Mem0、MemOS、Graphiti 已提供抽取、去重、图记忆等能力。全部自研会重复造轮子；直接依赖又会绑定其数据模型、部署与许可，且难以做“治理 + 经验晋升”的差异化。

- **不做 fork**：不复制其代码库；以依赖/服务方式集成，保留许可证与升级路径。
- **W2 spike**：用 100 条 Episode 比较“自研抽取”与“Mem0 抽取”的精确率/成本/延迟；再决定是否替换 `Extractor` 实现。
- **调研补充（2026-10-21）**：mcp-memory-service（bootstrap profile）、Memobase（结构化画像抽取）、Letta MemFS（root 身份 + lazy 目录 + Git）、MemOS（L1/L2/L3 + Skill）均有可借鉴部分；完整评估、复用矩阵与三条路线见[开源复用调研](../调研/MemoryBridge-开源复用调研.md)。

### 备选

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 全自研 | 可控、差异化 | 重复造轮子、慢 | 部分采用 |
| 直接基于 Mem0 | 快 | 数据模型/治理受限 | 仅作 Extractor 候选 |
| 基于 MemOS | 分层经验现成 | 部署重、绑定 Cube | 仅参考 |
| Graphiti 做图 | 时序强 | 图库运维重 | P2 可选 |

### 后果

- 正面：核心资产（schema/治理/同步/评测）自主；上游可换。
- 代价：抽取/检索要自己调；短期比“直接用 Mem0”慢。
- 风险：上游许可证/接口变化；适配层需测试。

### 验证与回滚

W2 spike 产出对比表；若自研抽取精确率明显低且成本高，`Extractor` 切换到 Mem0 OSS，其他层不变。若 Graphiti 在时序查询上显著优，P2 以 `GraphStore` 适配接入。

## ADR-016：评测——公开基准 + CrossProjectBench + 消融

**状态：已采纳（工程）｜日期：2026-10-21｜复审：W9/W11**

### 背景

只跑 LoCoMo/LongMemEval 只能证明“会记对话”，不能证明“跨项目经验迁移”。只做 demo 则无法回答“有没有用”。课程论文需要可复现的对照与统计。

### 决策

- **公开基准**：LoCoMo（10 段对话）、LongMemEval-S（500 题或子集），用于检索/问答质量对比。
- **自建 CrossProjectBench**：3 组项目对 × 12 任务（每组 A 学 6、B 测 6），rubric + 双人盲评（κ≥0.6）。
- **基线**：B0 无记忆、B1 全上下文、B2 朴素 RAG、B3 结构化记忆（Mem0 式）、B4 本方案无经验、B5 完整。
- **消融**：−图扩展、−重排、−冲突合并、−时效、−晋升门槛、−文档记忆。
- **安全/同步**：密钥 50 条、投毒 20 条、3 设备 200 op 收敛。
- **统计**：bootstrap 10k CI；配对 Wilcoxon；效应量（Cliff's delta）；α=0.05 + 多重比较校正。

### 备选

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 只跑公开基准 | 省事、可比 | 不测迁移 | 不够 |
| 只做用户研究 | 真实 | 样本小、不可复现 | 不做 |
| 公开 + 自建 + 消融 | 可复现、能证伪 | 基准构建成本 | **采用** |

### 后果

- 正面：论文有 RQ/假设/对照/消融；负结果也可解释。
- 代价：CrossProjectBench 构建 1–2 周；36 任务统计功效有限，需报告效应量与 CI。
- 风险：自建基准构念效度；需在报告中讨论任务代表性。

### 验证与回滚

G3（W9）基准 v0.1 可跑；G4（W11）至少 2/3 项目对 ≥10% 相对增益。若增益不显著，转“负结果 + 误差分析”，不伪造显著性。
