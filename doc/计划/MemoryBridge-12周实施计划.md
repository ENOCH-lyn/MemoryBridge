# MemoryBridge 12 周实施计划

- 状态：规划（未开始执行）
- 前提：3 人小组，每人每周约 10 小时；单用户、2 设备、3 个 agent、3 个项目
- 需求基线：[产品需求文档](../需求/MemoryBridge-产品需求文档.md)
- 评测方案：见 PRD 第 7 章（后续拆分为 `doc/测试/`）

## 1. 里程碑

| 周 | 目标 | 交付 / 门槛 |
|---|---|---|
| W1 | 调研、需求、范围 | 调研报告 + PRD（G0） |
| W2 | 架构、数据模型、API 契约、UI 线框 | 架构图 + OpenAPI 草案 |
| W3 | Hub 骨架、认证、space、记忆 CRUD | 本地可跑 |
| W4 | MCP 接入 + 采集 + 脱敏 | 2 个 agent 闭环（G1） |
| W5 | 抽取 + 去重 + 审核队列 | 100 条样本抽取评测 |
| W6 | 混合检索 + Context Pack + 反馈 | 检索 P@5 初测 |
| W7 | 同步协议 + 离线队列 + 冲突 | 2 设备收敛（G2） |
| W8 | 文档库 + Git + 上传解析 | 文档引用演示 |
| W9 | 经验蒸馏 + 验证 + 晋升 | 3 条 Skill 晋升；基准 v0.1（G3） |
| W10 | 控制台完善 + 安全加固 | 审核/同步/审计页面 |
| W11 | 实验：基线/消融/安全/同步 | 结果表 + 图（G4） |
| W12 | 部署、演示、报告、答辩 | 视频 + PPT + 最终报告 |

## 2. Go/No-Go 门槛

- **G1（W4）**：两个 agent 完成“采集 → 检索 → 注入”闭环。
- **G2（W7）**：两台设备并发编辑后同步收敛，无丢失更新。
- **G3（W9）**：CrossProjectBench v0.1 完成，基线可跑。
- **G4（W11）**：至少 2/3 项目对出现 ≥10% 相对增益；否则转为“负结果 + 误差分析”报告。

未达门槛时的处置：先砍 P1（文档库、控制台美化、图扩展），保 P0（采集、抽取、检索、同步、治理）；仍不达标则缩小研究问题，保“同步正确性 / 安全”作为第二贡献。

## 3. 分工

| 角色 | 负责 | 主要产出 |
|---|---|---|
| A 后端 / 同步 / 基础设施 | Hub API、DB、op log、部署、备份 | 可部署服务、同步测试 |
| B 记忆流水线 / 评测 | 抽取、去重、检索、经验蒸馏、基准 | 评测报告、数据集 |
| C 前端 / 文档 / 演示 | 控制台、文档库、Demo、PPT/视频 | 可演示界面、答辩材料 |

两人组：A 兼 C 的部分；一人组：砍到“MCP + 记忆 CRUD + 检索 + 单机双客户端”，不做同步。

| 风险 | 对策 |

| 范围蔓延 | 锁定 P0；P1 按周裁剪 |
